# DECISIONS (orchestrator-owned; D1–D9 are in the plan, section 3)

- 2026-09-30 D10. Module layout: one wasm module per program; the runtime WAT is prepended as text by the driver (as the probe does) until Phase 2 turns it into generated sections. Exports: `_main` (runs top-level forms in order) plus every defn by name.
- 2026-09-30 D11. Host imports for Phase 1 are exactly: `env.print_i64`, `env.print_str` (utf-8 ptr+len or array ref), `env.print_nl`; everything a scalar program prints goes through them. Phase 2 replaces them with `str`/`pr-str` in the runtime and one `env.write` import.
- 2026-09-30 D12. The runner `checks/wasm-run.sh <prog.lg>` compiles with the driver, assembles with wasm-tools, runs under node, and mirrors lg's observable behaviour: program stdout to stdout, exit 0 on success, non-zero with an `error: <message>` first line on an uncaught exception (so oracle.sh's normalised comparison works).
- 2026-09-30 D13. `.expected` files beside corpus programs are snapshots of native lg's stdout; `run-corpus.sh` fails STALE-EXPECTED if native lg no longer produces them, THEN calls oracle.sh. oracle.sh itself never reads them. Catches hand edits and lg drift the oracle would silently follow.
- 2026-09-30 D14. run-corpus.sh exit precedence: any MISMATCH or STALE → 1; otherwise anything short of all-MATCH (NOT IMPLEMENTED) → 2; all MATCH → 0.
- 2026-09-30 D15. `/` on ints yields ratios and, for MinInt64/-1, a bigint. Those are runtime value types (Phase 2). The div-*.lg op-matrix programs are skipped by P1.1 (run-corpus.sh honours a `SKIP` file in the corpus dir listing basenames) and re-enter at P2.7. `quot` stays in Phase 1.
- 2026-09-30 D16. Native quirks the backend must reproduce, not fix: (quot MinInt64 -1) = MinInt64; (- MinInt64) = MinInt64 while (- MinInt64 1) and (dec MinInt64) throw; shift counts ≥ 64 or negative follow Go (0 or sign), never throw; overflow message carries an `ExecutionError:` prefix, divide-by-zero does not.
- 2026-09-30 D17. P1.1's programs wrap every application in try/catch, so P1.1 cannot go green before P1.2 lands `:try`. Order within Phase 1 is therefore P1.0 → P1.2 → P1.1 ∥ P1.3 ∥ P1.4.
- 2026-09-30 D18. Hash hook contract: `checks/wasm-hash.sh <edn> <kind>` prints one decimal uint32. `<kind>` is required because `[]` hashes differently as ArrayVector vs PersistentVector. Non-finite floats are spelled `##NaN` `##Inf` `##-Inf` in vectors.tsv.
- 2026-09-30 D19. The wasm port reproduces let-go's hashing bit for bit INCLUDING its quirks (see FINDINGS.md H1–H5): empty-seq/[] split, -0.0 ≠ 0.0 hash, map entry hash = hash(k) ^ hash(v), the shared 64-bit finalizer across Int/Char/Float/BigInt, keyword = symbol + 0x9e3779b9. Parity first; fixing them is an upstream conversation after the campaign, phrased as plain hashing bugs.
- 2026-09-30 D20. Macroexpansion leaves qualified heads (`core/<`, `core/inc`); ir.build keeps them as var calls. The backend lowers calls whose target var is one of `#'< <= > >= + - * inc dec` as the matching IR op. `=` stays a call (polymorphic).
- 2026-09-30 D21. Legalize threads `:load-var` through blocks as block-args; values `ir/resolve-single-source` resolves to a var get no local and no edge copy and lower only in callee position; dead `:invalid` block params get no copy. A var used as a VALUE is an error until P1.3 (var table).
- 2026-09-30 D22. Booleans box to two `$Bool` singleton globals. Ints still box to `$Int` structs; the hybrid i31 of D2 is an explicit P1.1/P1.3 follow-up, not done in P1.0.
- 2026-09-30 D23. Driver: every defn body goes through `ir.passes.pipeline/expand-all` before `build-fn` (build-fn does not macroexpand). `ns`/`defn` forms are eval'd in a `user` ns so vars resolve; other `def*` heads are a named error; remaining top-level forms run in order in `_main`.
- 2026-10-01 D24. Intrinsics (`rt/wasm/intrinsics.lg`, ns `wasm.intrinsics`, 42 fns + `defstruct`/`defarray`/`deffunc`): the wasm instruction and typeinfer signature live in `:wasm`/`:type` var metadata so the backend and the coverage test read them mechanically. Operands/results are lg types (`:int`=i64, `:bool`=i32, `:any`=(ref null eq)); i32/i8 are storage only and each intrinsic's expansion carries its own wrap/extend. Mutable fields are `[:mut t]`. `new`/`call-ref` arity is fixed by the declaration.
- 2026-10-01 D25. No `wasm/throw`/`wasm/try`: lg `try` + `core/throw` (P1.2) for catchable errors; `wasm/trap` (uncatchable) for internal invariants. All runtime types go in ONE `(rec ...)` group so same-shaped structs stay distinct under `ref.test`.
- 2026-10-01 D26. Reference impl is stricter than wasm where wasm is silent (out-of-range i31, index ≥ 2^32, raw lg value in a :ref slot, out-of-range :i32 all throw). OPEN for the backend: bounds-check indices in i64 or accept the i32-wrap divergence; decide at P2.1-backend.
- 2026-10-01 D27. Host calls in the reference are deterministic (virtual clock advanced only by host-sleep; env from `*host-env*`). `bytes-of-string` is literal-only in wasm (`array.new_data`).
- 2026-10-01 D28. Gap: float hashing needs `f64-bits` (`i64.reinterpret_f64`), absent from the set and not computable in native lg without interop. P2.2-wasm adds the intrinsic; the reference impl may use a Go-side helper via a tiny native, or skip float rows under `--native`.
- 2026-10-01 D29. Map order spec = `corpus/maporder/SPEC.md` (let-go 4e769212): insertion-ordered array-map up to 8 entries (`arrayMapMaxEntries`, persistent_map.go:601) incl. `hash-map`; 9th key promotes to a 32-way HAMT (bitmap + collision nodes only, low 5 bits first, seq walks slots 0..31 depth-first); never demotes; sets are hash-ordered at every size. The port implements the node algorithms literally; collision-bucket order is history-dependent.
- 2026-10-01 D30. Parity includes the bucket 2→1 dissoc bug (FINDINGS M1). Go-map-sourced maps (json, transit, bencode, boxing) are out of the oracle's scope. maporder rows above 100 keys print head 16, tail 16 and a checksum.
- 2026-10-01 D31. Exceptions: try regions are lambda-lifted wasm functions; ONE tag `$lgex (param (ref null eq))` carries the thrown lg value; runtime errors are `$Err` kind 1 (uncaught message) reified to kind 2 on catch (`ex-message` then carries the `ExecutionError: ` prefix for overflow, none for divide-by-zero, as native); finally = catch_all_ref + throw_ref. Catch class table is strict (Throwable, Exception, ExceptionInfo, String + java./clojure.lang. spellings); other classes are compile errors.
- 2026-10-01 D32. The structurize gate rejects only trees containing a `:goto` node; `:multi`-exit loops are complete and lower (`:break` finds its loop by exit block). P1.6's metric is therefore `:goto` count, and `:switch` nodes (keyword cond chains) are P1.6's remaining work.
- 2026-10-01 D33. run.mjs runs the module on a worker thread with a 256 MB stack (native lg recurses past 3M frames; 100k-deep int recursion must not die). P1.GATE's timing compares like with like.
- 2026-10-01 D34. CONFLICT TO RESOLVE at P2.1-backend: P1.2 emits every wasm type as its own rec group (relying on structural distinctness); D25 requires ONE rec group. Move to one rec group when the intrinsics' `defstruct` types are emitted; until then new Phase-1 types ($Kw, $Map0, $Err) must stay structurally distinct.
- 2026-10-01 D35. Unary minus: build.lg turns `(- x)` into `(sub 0 x)` so `(- MinInt64)` throws in the IR path while native bytecode wraps (D16). Not distinguishable after build. Parity choice: the DRIVER rewrites unary `(- x)` to the unchecked form before build (what native does), documented; lower-go has the same divergence (upstream finding).
