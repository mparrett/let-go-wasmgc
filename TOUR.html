0. Play it

The emitted lane needs no cross-origin isolation, so any static server works. From dev/lower-wasm/:

host/build-xsofy-module.sh /tmp/lw-play/xsofy.wasm      # ~80 s compile + wasm-opt, cached by content
host/build-xsofy-serve.sh  /tmp/lw-serve /tmp/lw-play/xsofy.wasm
# the adapter's default module name
cp /tmp/lw-serve/xsofy.wasm /tmp/lw-serve/module.wasm
python3 -m http.server 8260 -d /tmp/lw-serve
open 'http://localhost:8260/index.html?seed=424242'

That is the real xsofy-shell.html, copied unchanged, driving the WasmGC module through window.LetGoHost. Seed 424242 is the one lane 5 proves byte-identical to the stock lane. ?module=<name>.wasm picks another module in the same directory.

2. Chapters

0. Plan and scaffold22:46 to 23:45, 6 commits

The probe (dev/emit-wasm-probe) had shown IR to WasmGC works at 120 to 860 times the speed of the VM in wasm. Plan v2 was fact-checked against the tree, then turned into a campaign where done means one thing: a row in items.tsv whose check exits 0. Every differential check goes through one match relation, oracle.sh (exit class, stdout bytes, normalised first error line). Corpora were materialised as files before any backend code was written: the 42-program op matrix, 201 hash vectors pulled from let-go's own vm.HashValue, the map-order oracle.

Why it mattered later: agents could not argue with a check, and I could verify every report by rerunning its row.

1. Phase 1: a strict backend on scalar code23:50 to 02:28, 11 commits, gate D62

Driver, strict control-tree walker (unknown op or tree node is an error, never a fallback), then wasm exception handling for try/throw/finally (one tag, lambda-lifted regions), then every scalar op typed and boxed with hybrid i31 boxing and Go's shift and quot semantics, then closures with the $Fn ABI and a var table. The gate added the refusal corpus, a census of xsofy and legmacs showing zero op errors and zero goto fallbacks, :switch, tree-shaking and typed self-returns. fib(32) came in at 1.385 times the hand-written probe with checked arithmetic kept.

In parallel, three agents wrote the runtime's native halves in the constrained lg dialect over the 42 intrinsics (D24): persistent vector proof, seqs, maps and sets mirroring let-go's array-map and HAMT, strings with an exact port of Go's float formatting. All of it ran and was tested under native lg with reference intrinsics before the backend could compile a line of it. That decision (D4) is the one that made the schedule.

The quiet gap from 03:07 to 05:25 is the hardest item of the campaign being built. At 06:01 the backend compiled its own runtime: intrinsics emitted inline, every runtime type in one rec group, a content-addressed rtlib cache so the 90 second runtime analysis happens once, tree-shaking, and a test shim so let-go's own deftests can run under the backend. From there the pace is one landed item every 20 to 40 minutes:

  • the browser, node and wasmtime host with JSPI for sleep and read-key, so no cross-origin isolation is needed (D91)

  • the real xsofy shell booting an emitted module unmodified through LetGoHost
  • the internal dossier of upstream-worthy findings, phrased without naming this project

4. Closure capture, variadics, and a perf detour10:38 to 13:01, 7 commits

P2.11 fixed closure capture by id (an ir.build free-vars scope bug, upstream-worthy), strict CSE keys, float typing and NaN payloads. Two handoff notes mark where my own context compacted. D106 adopted the zero-risk part: a machine-wide slot pool, parallel corpus and census runs, no sleep polling. Then the variadic ABI landed as a $FnV subtype (D109).

5. xsofy, headless then in the browser13:57 to 17:10, 5 commits, gates D113 and D120

Multi-namespace driver, then world generation plus 60 turns byte-identical to native on 20 seeds (Phase 3 gate, 313 KB module). Then xsofy plays in the real shell from the emitted module. Lane 5 flaked between runs; the root cause was fixed-timing key injection, and the stock lane itself drops keys under load. The fix was a settle-based walk that sends the next key only after the shell reports the previous turn (D119). Phase 4 gate at 17:05: the plan's finish line.

6. Closing Phase 2 properly17:37 to 21:03, 8 commits, gate D127

With the finish line passed, the remaining Phase 2 debt was paid rather than waved through: parallel checks landed byte-identical to serial (P0.1), core tests went from 133 to 265 of 273 (stdlib loaded on demand, an RE2-subset regex engine, var and ns symbols), the hash hook hit zero misses after a reader NaN fix, map order reached 14 of 14 via an array-map twin, and let-go's examples were scoped with a written reason per skip. The gate passed with one named limit: a single to-array deftest. Then the summary, inventory and ADR pointer.

3. How the work ran

  • Three tiers. A Pulse coordinator session oversaw the board and relayed Matt's asks. One Fable session (the campaign runner) owned the plan, the decision log and every commit, and dispatched at most three Opus subagents at a time, roughly 40 dispatches in all. Items touching src/ ran one at a time; runtime items ran beside them. Mechanical work went to Sonnet. Every agent read AGENTS.md: write scopes, the match relation, "done = checks/run.sh <id>", falsify your own fix, no polling.
  • Every report was verified by rerunning its row before anything was committed. Each landed item is one commit naming its D-numbers. DECISIONS.md is the binding log (D1 to D9 in the plan, D10 to D127 here); STATUS.md was the live board; FINDINGS.md holds what was learned but not decided.
  • Two adversarial reviews and one perf investigation were separate agents with read-only briefs and their own corpora, so their findings could not be argued away.
  • Nothing left the machine. let-go, xsofy and docs-xsofy checkouts are untouched; no worktrees; the backend consumes a stock lg at the pinned SHA as a library. ORCHESTRATOR-HANDOFF.md records the standing rules and the compaction points.

Round-3 chapters

E0. The seamwritten before dispatch, D160 to D162

Two builders worked in parallel on opposite sides of one interface, written down in ROUND3.md ("Phase 7 seam") before either started. A owns rt/: rt/wasm/eval.lg in namespace wasm.eval, plain lg like natives.lg (load order 17), claiming core/eval through the usual ^{:twin ...}, so a program that never calls eval (xsofy) pays nothing. B owns src/: the driver emits a program table when the program reaches eval. Neither edited the other's files; I integrated. The table's shape, installed from ns-init after every library init:

(wasm.eval/install-program-table!
  {"legmacs.main" {:aliases {"buf" "legmacs.buffer"}
                   :refers  {"vibe" "legmacs.vibe"}
                   :vars    {"x" #'legmacs.main/x}
                   :macros  {"defcommand" <macro fn>}}
   ...})

The resolution order for a symbol evaluated in the current namespace (the header of eval.lg states it, D160 records the one deviation from the seam): a local, a cell of the current ns, the table's :vars, the table's :refers, a cell interned into let-go.core (native's baseline refer; legmacs.vibe interns vibe there), then the core table for an unqualified name. a/s goes through the registry's aliases of the current ns, then the table's, then a as a full ns name. Following native, let-go.core/s and user/s do not reach the core table. Not found raises native's Can't resolve s in this context with native's CompileError layers around it.

E1. The evaluator's shapeagent A, D160, 2026-10-02

(compile form cenv) turns a form into an lg fn of the run-time environment once, and evaluation runs the closures: the dispatch on syntax happens once per form, not once per evaluation. An evaluated fn is an ordinary variadic lg closure that picks its arity inside, so it is a $Fn like any other and works in atoms, map, apply and key bindings. Pieces:

  • Special forms: 11 native ones (if do def set! fn* quote var let* loop* recur try, as compiler.go has them). loop/recur pass a sentinel to the loop in the compiled closure. try is lg's try; finally runs after the catch and the outcome is rethrown.
  • Core macros as expanders: about 40 of them (defn let fn cond case for doseq binding ns and the rest), ported from core.lg as functions that build native's exact forms, so the CompileError chains nest the way native prints them.
  • The core table: a map of about 230 names to fn values, written as plain lg values so the backend links each twin because eval.lg names it. A core name outside it is Can't resolve here.
  • Registry cells: def/defn/defmacro intern a cell ns/name in wasm.natives' registry; its var is a #'ns/name stand-in with an :lw/var getter, so deref, calls through the var and the var natives all work. Evaluation never writes a program var.
  • The reader code hook: #(, ::kw, syntax-quote and #"re" read as code through a hook kept in the root of #'wasm.reader/code-hook; there is no reader global.

The evaluator uses only core fns, so it also runs under native lg on native values: corpus/intrinsics/eval_test.lg compares it with native eval (122 tests, 37,970 asserts on 2026-10-02). That is what let agent A work against an oracle before the backend half existed.

E2. The backend halfagent B, D161 and D166, 2026-10-02

When the program's forms name eval or *ns*, _main opens with (in-ns '<main ns>), and when eval is reached it calls install-program-table! after the library inits. Per program namespace the driver compiles two hidden defns in that namespace (so privates and its aliases resolve): __lw_pvar, a binary search over qualified var reads that every table stand-in's getter shares, and __lw_ptab, the entry. Each program defmacro becomes a hidden __lw_m_<name> fn of exactly its declared params, &form/&env nil; legmacs' defcommand expands identically to native macroexpand-1. Reads of *ns* route to wasm.natives/current-ns.

Cost (brotli, legmacs, 2026-10-02): round 2's 119,059 B, then 142,113 B with eval.lg alone (+23 KB), then 166,102 B with the table (+24 KB). The table is mostly that every program def becomes reachable as a value, so tree-shaking can no longer drop the unused ones. That stayed under the 40 KB threshold the seam set for switching to lazy stand-ins, so the eager map stayed. Later fixes put the default module at 166,284 B (D163). Eval-free programs are untouched: xsofy's wasm-opt output was byte-identical across the table change.

D166 added what the review found on this side: a defn in user before the file's (ns ..) form no longer makes the driver refuse the program, and an uncaught CompileError out of eval or a program fn gains native's error: calling f layer (lw-ext/calling-throw; a caught error keeps native's ex-message).

Round 3: what is open

  • Named limits of the evaluator (D160 to D166, all in the eval.lg header or the decision): tail calls between evaluated fns are not trampolined (deep non-loop recursion grows the wasm stack); catch does not dispatch on the class, the first clause catches everything; no go or channels (Phase 8); no host interop, deftype, defprotocol, defmulti, macroexpand; a future is never pending (D162); the core table is a subset, so other core names are Can't resolve.
  • Redefinition does not reach compiled callers: evaluation never writes a program var, so after an evaluated (defn mine ..) a compiled caller of mine still calls the original. binding, set!, var-get and alter-var-root of a program var raise a named limit.
  • An eval reached only through a macro expansion gets no table (D161), and table stand-ins carry only :name and :ns.
  • p06 (D166): a top-level (eval '(in-ns 'x)) does not move the statically compiled forms after it; each form compiles in the ns the driver saw. Probably inherent to static compilation, so recorded rather than fixed.
  • e07 (D166): (eval *ns*) resolves the namespace stand-in as a symbol (Can't resolve <ns user>) where native refuses with cannot compile a value of type let-go.lang.Namespace as a form. eval.lg, not taken this round.
  • The macro error frames (D165): apart from let/loop destructure frames and when-let/when-first's calling throw, an error inside a macro carries only the root message, where native inserts its per-call caused by ExecutionError: calling X frames.
  • Smaller, recorded: swap! with 19 or more extra args (D164); gensym numbering differs; an evaluated (resolve 'a/priv) from another ns may still return the var where native gives nil (open, unverified, D165); the wasmtime adapter does not export env.getenv yet (D159); the legmacs files commands and vibe stay at 0 (no file system; builtin namespaces' publics).
  • Decisions for Matt: the public surface of eval is undecided, and Track B (repo split, README, demo page, upstream issues) waits for him after the test-drive.
