0. Play it

The emitted lane needs no cross-origin isolation, so any static server works. From dev/lower-wasm/:

host/build-xsofy-module.sh /tmp/lw-play/xsofy.wasm      # ~80 s compile + wasm-opt, cached by content
host/build-xsofy-serve.sh  /tmp/lw-serve /tmp/lw-play/xsofy.wasm
cp /tmp/lw-serve/xsofy.wasm /tmp/lw-serve/module.wasm      # the adapter's default module name
python3 -m http.server 8260 -d /tmp/lw-serve
open 'http://localhost:8260/index.html?seed=424242'

That is the real xsofy-shell.html, copied unchanged, driving the WasmGC module through window.LetGoHost. Seed 424242 is the one lane 5 proves byte-identical to the stock lane. ?module=<name>.wasm picks another module in the same directory.

2. Chapters

0. Plan and scaffold22:46 to 23:45, 6 commits

The probe (dev/emit-wasm-probe) had shown IR to WasmGC works at 120 to 860 times the speed of the VM in wasm. Plan v2 was fact-checked against the tree, then turned into a campaign where done means one thing: a row in items.tsv whose check exits 0. Every differential check goes through one match relation, oracle.sh (exit class, stdout bytes, normalised first error line). Corpora were materialised as files before any backend code was written: the 42-program op matrix, 201 hash vectors pulled from let-go's own vm.HashValue, the map-order oracle.

Why it mattered later: agents could not argue with a check, and I could verify every report by rerunning its row.

1. Phase 1: a strict backend on scalar code23:50 to 02:28, 11 commits, gate D62

Driver, strict control-tree walker (unknown op or tree node is an error, never a fallback), then wasm exception handling for try/throw/finally (one tag, lambda-lifted regions), then every scalar op typed and boxed with hybrid i31 boxing and Go's shift and quot semantics, then closures with the $Fn ABI and a var table. The gate added the refusal corpus, a census of xsofy and legmacs showing zero op errors and zero goto fallbacks, :switch, tree-shaking and typed self-returns. fib(32) came in at 1.385 times the hand-written probe with checked arithmetic kept.

In parallel, three agents wrote the runtime's native halves in the constrained lg dialect over the 42 intrinsics (D24): persistent vector proof, seqs, maps and sets mirroring let-go's array-map and HAMT, strings with an exact port of Go's float formatting. All of it ran and was tested under native lg with reference intrinsics before the backend could compile a line of it. That decision (D4) is the one that made the schedule.

2. First adversarial review, and the EDN reader02:53 to 03:07, 3 commits

A reviewer agent was briefed to break "the backend is correct on the Phase 1 subset": 148 probes, 11 bugs, 2 gaps, written up in corpus/review and turned into item P1.7. Meanwhile the data reader landed in the dialect with a 951-case parity run against native read-string.

3. The hinge: the runtime compiled through the backend05:25 to 08:45, 10 commits

The quiet gap from 03:07 to 05:25 is the hardest item of the campaign being built. At 06:01 the backend compiled its own runtime: intrinsics emitted inline, every runtime type in one rec group, a content-addressed rtlib cache so the 90 second runtime analysis happens once, tree-shaking, and a test shim so let-go's own deftests can run under the backend. From there the pace is one landed item every 20 to 40 minutes:

  • the second adversarial review, a 2300-seed differential fuzz of the runtime (16 bugs, corpus/review2), and its fix item
  • the 14 oracle programs in corpus/wasm, which surfaced nine backend bugs and proved variadics were not optional (D83)
  • xsofy's natives: typed arrays, math, a canonical XXH3 port, host io and time
  • the browser, node and wasmtime host with JSPI for sleep and read-key, so no cross-origin isolation is needed (D91)
  • the Phase 1 review fixes: param-typing fixpoint, purity pins, tail calls via return_call, id munging
  • the real xsofy shell booting an emitted module unmodified through LetGoHost
  • the internal dossier of upstream-worthy findings, phrased without naming this project

4. Closure capture, variadics, and a perf detour10:38 to 13:01, 7 commits

P2.11 fixed closure capture by id (an ir.build free-vars scope bug, upstream-worthy), strict CSE keys, float typing and NaN payloads. Two handoff notes mark where my own context compacted. Matt asked, via the coordinator, for a look at why checks were slow: a read-only agent found the laptop oversubscribed and the same check varying 5.8 times with load alone (perf-report.md). D106 adopted the zero-risk part: a machine-wide slot pool, parallel corpus and census runs, no sleep polling. Then the variadic ABI landed as a $FnV subtype (D109).

5. xsofy, headless then in the browser13:57 to 17:10, 5 commits, gates D113 and D120

Multi-namespace driver, then world generation plus 60 turns byte-identical to native on 20 seeds (Phase 3 gate, 313 KB module). Then xsofy plays in the real shell from the emitted module. Lane 5 flaked between runs; the root cause was fixed-timing key injection, and the stock lane itself drops keys under load. The fix was a settle-based walk that sends the next key only after the shell reports the previous turn (D119). Phase 4 gate at 17:05: the plan's finish line.

6. Closing Phase 2 properly17:37 to 21:03, 8 commits, gate D127

With the finish line passed, the remaining Phase 2 debt was paid rather than waved through: parallel checks landed byte-identical to serial (P0.1), core tests went from 133 to 265 of 273 (stdlib loaded on demand, an RE2-subset regex engine, var and ns symbols), the hash hook hit zero misses after a reader NaN fix, map order reached 14 of 14 via an array-map twin, and let-go's examples were scoped with a written reason per skip. The gate passed with one named limit: a single to-array deftest. Then the summary, inventory and ADR pointer.

3. How the work ran

  • Three tiers. A Pulse coordinator session oversaw the board and relayed Matt's asks. One Fable session (the campaign runner) owned the plan, the decision log and every commit, and dispatched at most three Opus subagents at a time, roughly 40 dispatches in all. Items touching src/ ran one at a time; runtime items ran beside them. Mechanical work went to Sonnet. Every agent read AGENTS.md: write scopes, the match relation, "done = checks/run.sh <id>", falsify your own fix, no polling.
  • Every report was verified by rerunning its row before anything was committed. Each landed item is one commit naming its D-numbers. DECISIONS.md is the binding log (D1 to D9 in the plan, D10 to D127 here); STATUS.md was the live board; FINDINGS.md holds what was learned but not decided.
  • Two adversarial reviews and one perf investigation were separate agents with read-only briefs and their own corpora, so their findings could not be argued away.
  • Nothing left the machine. let-go, xsofy and docs-xsofy checkouts are untouched; no worktrees; the backend consumes a stock lg at the pinned SHA as a library. ORCHESTRATOR-HANDOFF.md records the standing rules and the compaction points.

src/lower_wasm.lg:1128

src/lower_wasm.lg:1572

src/lower_wasm.lg:1669

src/lower_wasm.lg:2027

src/lower_wasm.lg:2153

src/lower_wasm.lg:3372

src/lower_wasm.lg:3608

The runtime: rt/wasm/ (about 7,200 lines of lg over 43 intrinsics)

rt/wasm/intrinsics.lg:1
The contract. Each intrinsic has a reference implementation (so the runtime runs natively) and :wasm/:type metadata (so the backend emits it). defstruct, defarray, deffunc declare the GC types.
rt/wasm/seq.lg:278
One file owns every box and its kind tag (kinds 0 to 37) with per-kind hooks (D59). The chunk and realisation behaviour mirrors let-go's lazy seqs so printing a half-realised seq matches.
rt/wasm/phm.lg:309
The persistent map, a literal port of persistent_map.go: array-map to 8 entries, then a 32-way HAMT. This comment marks the deliberately reproduced collision-bucket dissoc bug (D30), the clearest example of parity-with-quirks.
rt/wasm/phm.lg:117
mix-finish and the hash helpers: FNV-1a for strings, the Murmur3 mixes, the shared 64-bit finaliser. These are what the 201-vector hash corpus checks to the bit.
rt/wasm/str.lg:358
round-shortest!: Go's strconv shortest-float formatting ported so (str 0.1) and friends print identically. The 2000-instruction function that motivated the memoised src-of in the backend.
rt/wasm/reader.lg:980
read-string*: the data reader, 951-case parity, exact float parse, and the ##NaN literal that closed the last hash miss (D123).
rt/wasm/xxhash.lg:210
XXH3-64 with seed, the hash xsofy's determinism rests on, ported canonically. Byte-identical world generation depends on this file.
rt/wasm/host.lg:1
The natives that reach outside: print, write, sleep, nanotime, getenv, emit, url_param. term.lg beside it is read-key, key-pending and size with exact escape sequences.
